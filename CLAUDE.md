# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
make install   # Install Go deps + download Tailwind CSS standalone binary to bin/
make dev       # Dev server: Air (Go hot reload) + Tailwind CSS watcher
make build     # Production build: minify CSS, compile Go binary to bin/server
make test      # go test ./...
make fmt       # go fmt ./...
make lint      # golangci-lint run
```

Run a single test package: `go test ./internal/database/...`

On first clone, also run `git lfs install --local && git lfs pull` to fetch `artworks.db`.

## Environment

Copy `.env.example` to `.env`. Key variables:

- `OPENROUTER_API_KEY` — required for artwork generation; without it generation is disabled but the gallery still works
- `ENABLE_EDITING` — gates all write operations (workshop, create/update/delete endpoints); defaults to `false`, which also opens SQLite in read-only mode
- `PORT` — defaults to `8080`

## Architecture

**Go backend** (`main.go` + `internal/`) uses only the standard library for routing — no framework. `main.go` owns all route registration and middleware (logging, rate limiting). Page handlers live in `internal/pages/pages.go`; JSON API handlers in `internal/api/handlers.go`.

**Template rendering** uses `html/template` with all templates in `templates/*.html`. In dev mode (`GO_ENV != "production"`) templates are re-parsed on every request for hot reload. In production they are embedded via `//go:embed` and cached. The `frame`, `footer`, and `plausible` partials are defined in `templates/partials.html` and shared across pages.

**Database** is SQLite (`artworks.db`, tracked via Git LFS) accessed through `modernc.org/sqlite` (pure Go, no CGO). Schema: `artwork_groups` (one per painting prompt) → `artworks` (one per model response, stores raw SVG). The `featured` boolean on `artworks` controls which artwork appears in the gallery grid for a group. Categories are a plain text field on `artwork_groups`.

**CSS** — Tailwind CSS v4 with a CSS-first `@theme` in `static/css/input.css`. Never edit `output.css` directly; it is regenerated by the Tailwind standalone binary. `output.css` is cache-busted via an MD5 hash passed as `.CSSHash` in every template data struct.

**Frontend JS** — The workshop page uses Preact + HTM loaded from `esm.sh` (no build step). The JS is split into ES modules under `static/js/modules/` (state, api, components, modals). All other pages are server-rendered with no client-side JS beyond the artwork-group filter sidebar.

**AI generation** — All model calls go through OpenRouter. Available models are fetched from the OpenRouter API and cached for 5 minutes in memory (`internal/config/config.go`). The prompt template lives in `config/prompt.yaml`.

**Routing** — `/` redirects to `/gallery/category/abstract`. `/gallery/category/{name}` serves the gallery grid filtered by category. `/group/{id}` shows all model outputs for one painting. `/about` is the informational page. `/workshop` is edit-gated by `ENABLE_EDITING`.
